# M5 — Studio (Mac review and edit app)

> Execute inline. Per the user: no unit tests; verify with e2e tests and a real run on `IMG/`.

**Goal:** A SwiftUI Mac app that opens a completed run, shows the three concepts side by side, and supports only the spec's edits: reorder, swap, remove and reroll. It exports ordered slides, shares them, and logs every interaction. Original plan artifacts are never modified.

**Spec:** §9.2 (Studio UX), §9.3 (run directory, interaction-events.jsonl), §9.5 (interaction logging), §12 M5 exit demo.

## Architecture

- **New library target `Session`** (depends on Core and Render). It holds all editing, rendering, export and logging logic, so the e2e tests drive exactly what the UI drives.
  - `ConceptRendering` moves here from CLI unchanged. CLI and Session share it.
  - `PlanEditor` (Core, pure): `reorder(plan, from, to)`, `swap(plan, slide, photo, with:)`, `remove(plan, slide, photo)`. When a slide empties, the slide is dropped. When a photo count no longer fits the primitive, it's downgraded the same way the resolver does it. Plain stays one photo per slide.
  - `RunSession` (class, `@MainActor`-free, `Sendable` via a lock): `open(runDirectory:)`, `concepts`, `workingPlan(concept)`, `apply(edit, concept)`, `reroll(concept)` (new layout seed; no model call), `render(concept)`, `export(concept, to folder)`, `swapCandidates(concept, slide, photo)`, `log(event)`.
- **Swap candidates:** first the photo's own shot-cluster alternates (from `cache/reduction.json`), then the rest of the planning pool, excluding photos already in the concept.
- **Edited artifacts** live in `edits/<concept>/`: `plan.json`, `seed.txt`, `slides/slide-NN.png`, `layouts/`. `plans/` and `slides/` from the run are never touched. The first edit copies the original plan.
- **Interaction events:** `interaction-events.jsonl`, append-only, one JSON object per line:
  - fields: `eventID`, `runID`, UTC `timestamp`, `event`, `conceptID?`, `slideIndex?`, `assetIDs?`, `before?`, `after?`, `source: "operator" | "participant"`
  - events: `concepts_presented`, `concept_selected`, `concept_rerolled`, `photo_swapped`, `photo_removed`, `slide_reordered`, `carousel_exported`, `carousel_shared`, `edit_session`
  - no image content, no free text
- **Source folder:** asked for once per run (NSOpenPanel) and remembered in the app's UserDefaults keyed by runID, never in the run directory. The same SHA check as `rerender` runs before rendering edits.
- **Studio app** (`executableTarget` `Studio`, SwiftUI, macOS 27):
  - a run picker (recent `runs/`)
  - a three-column concept board with slide strips at 3:4, 4:5 or 1:1
  - a selected slide shows its photos with Swap (a popover of candidates) and Remove buttons
  - slides reorder by drag, or with ←/→ buttons
  - Reroll layout button
  - "Use this concept" logs `concept_selected`
  - Export to a folder (ordered PNGs), and Share via NSSharingServicePicker
  - progress text uses the spec's four stage names when rendering
  - no arbitrary positioning, resizing or type editing
